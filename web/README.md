# Blocks Builder

Visual model builder for `models/blocks` with strict jaxtyping shape inference.

A two-pane app:

- **Left palette** — every block exported from `pytorch_blocks` or `flax_blocks`
  (with shape info extracted from their jaxtyping annotations).
- **Centre canvas** — a [Rete.js v2](https://retejs.org) graph editor.
  Drag a block to add a node; wire `out` ports into `in` ports.
- **Right sidebar** — Diagnostics panel (errors / warnings) plus an Inspector
  for editing the selected node's constructor parameters and seeing each
  port's *resolved* shape.

The editor enforces three layers of correctness:

1. **At connection time** — every edge is dry-run through a unifier
   (`src/unify.js`). If the producer's output shape can't unify with the
   consumer's input, the connection is refused on the spot.
2. **Continuously, on the whole graph** — after every change the validator
   re-unifies all edges and posts errors / warnings to the Diagnostics panel.
   Constructor parameters that the manifest maps to axes (e.g. `out_ch ↔
   C_out`) are bound *first*, so a wrongly-sized downstream block immediately
   shows up as a literal mismatch.
3. **At codegen time** — the topological sort detects cycles, multi-output
   nodes are destructured, variadic ports collected into lists, and the
   output is a runnable `nn.Module` / `nnx.Module` subclass.

## Stack

- Vite + plain ES modules (no React / Vue framework, but the rete v2 Lit
  plugin handles node rendering since rete v2 has no pure-vanilla renderer).
- Manifests in `public/manifests/{pytorch,flax}.json` are generated by
  `python tools/build_manifest.py` at the repo root.

## Run

```bash
# 1. (Re-)generate the manifests. Needs the Python deps (jax / torch /
#    flax / jaxtyping). CHECK_TYPES=0 to skip beartype during introspection.
python tools/build_manifest.py

# 2. From web/:
npm install
npm run dev    # http://127.0.0.1:5173/
```

`npm run build` produces a static bundle in `web/dist/`.

## Tests

```bash
npm run test:logic     # pure-JS shape parser + unifier + codegen
npm run test:e2e       # headless puppeteer; expects `npm run dev` running
npm run test:runtime   # traced codegen + HTTP runner; start runner first
npm run test:info-tab  # info tab + Mermaid render + collapsibles
npm run test:autosave  # localStorage autosave + restore-on-reload
```

Run the Python shape runner (PyTorch only, separate terminal)::

```bash
python tools/shape_runner.py   # http://127.0.0.1:8765/run
```

Then in the UI sidebar **Runtime shapes → Run shape check** once every axis is numeric.

## Autosave

The current graph is saved to `localStorage` under `blocks-builder:autosave:v1`
on every structural change (node add/remove, connection add/remove), every
constructor value edit, every node drag, and every batch-size tweak. Saves are
debounced to 800 ms so rapid typing collapses to a single write. On boot, the
editor restores the slot automatically and flashes a brief
"Restored N node(s) from autosave" notice in the diagnostic strip. No UI pill,
no Save/Load buttons — just don't lose work to a misclick or refresh. To wipe
the slot, open DevTools and run
`localStorage.removeItem('blocks-builder:autosave:v1')`.

## Per-block Info tab (description + reference Mermaid)

The Inspector has two tabs: **Params** (constructor controls + resolved port
shapes) and **Info** (description blockquote, shape line, rendered reference
Mermaid, plus collapsible **Used in / Tasks / Common pitfalls / See also**
sections, all scraped from
[RealityShifts/Srivastava-book-of-Blocks-diagrams](https://github.com/RealityShifts/Srivastava-book-of-Blocks-diagrams)).
arXiv links in the **See also** lists are rendered as anchor tags; **See
also** opens by default, the other three sections start collapsed.

Refresh the cached scrape any time the upstream repo updates:

```bash
python tools/fetch_block_diagrams.py
# → web/public/block_info.json   (~124 entries, served by Vite)
```

Coverage on the current manifests: ~90% of PyTorch blocks and ~83% of Flax
blocks have a reference diagram. Blocks the upstream doesn't document
(`scaled_dot_product_attention`, `clip_grad_norm`, etc.) show a "No reference
diagram" fallback. The Mermaid is rendered client-side via `mermaid@^11.15`.

Smoke test::

```bash
npm run test:info-tab    # expects `npm run dev` running
```

## Generate Mermaid For All Blocks

Create one Mermaid markdown file per block (PyTorch + Flax) from the generated
manifests:

```bash
# from repo root
python tools/generate_mermaid_blocks.py
```

Outputs are written to:

```text
diagrams/
  pytorch/<module_tail>/<Block>.md
  flax/<module_tail>/<Block>.md
```

This gives a local equivalent of the diagrams workflow in
[RealityShifts/Srivastava-book-of-Blocks-diagrams](https://github.com/RealityShifts/Srivastava-book-of-Blocks-diagrams.git).

## File map

```
src/
  shape.js       parse / freshen / pretty-print jaxtyping shape tokens
  unify.js       Hindley–Milner unification on axis variables (rest-aware)
  nodes.js       BlockNode (extends ClassicPreset.Node) built from a manifest
  validator.js   walks the live graph, unifies every edge, emits diagnostics
  codegen.js     graph → Python module (PyTorch or Flax)
  ui.js          palette + inspector + diagnostics DOM
  main.js        Rete bootstrap, pipe wiring, toolbar
  style.css      theme

public/manifests/  pytorch.json / flax.json (generated)
```

## Manifest schema

```json
{
  "name": "ConvBlock",
  "module": "pytorch_blocks.core_blocks",
  "framework": "pytorch",
  "kind": "module",                     // or "function"
  "ctor": [
    {"name": "in_ch", "type": "int", "default": null, "required": true},
    ...
  ],
  "inputs":  [{"name": "x",   "shape": ["B","C_in","H","W"],     "dtype": "float", "optional": false, "variadic": false}],
  "outputs": [{"name": "out", "shape": ["B","C_out","H_out","W_out"], "dtype": "float", "optional": false, "variadic": false}],
  "bindings": {"C_in": "in_ch", "C_out": "out_ch"}
}
```

Heuristic `bindings` are populated by suffix-matching common parameter names
(`in_ch ↔ C_in`, `dim ↔ D`, `latent ↔ Z`, …). They are what lets the
validator say *"this edge requires `C_in=64` but upstream produces 16"*
instead of just propagating an unbound variable.
